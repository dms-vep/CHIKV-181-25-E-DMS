# CLAUDE.md

## General principles
- This is scientific coding so it should fail fast with clear error messages if anything unexpected happens, do not silently pass over errors. For instance, when getting from dictionaries don't use `.get` with defaults unless that is specifically desired; instead raise an error if key does not exist.

- All input data go in `./data` and all results generated by the pipeline are placed in `./results`

- This is a Snakemake pipeline with the configuration in `config.yaml`, the conda environment in `environment.yaml`, the pipeline itself in `Snakefile`, and scripts in `./scripts`. 

- Each `snakemake` rule should have the following:
  - log: written to `results/logs/{rulename}_{wildcards}.txt`
  - conda directive: points to `environment.yaml`
  - as relevant, input, output, and params. Output is always written to an appropriate subdirectory in `results`

- Keep the code as concise as possible

- Do not duplicate code in scripts; define things (eg, lists of expected columns) in one place.

- Keep `README.md` updated with a description of pipeline

- The pipeline uses a single shared `conda` environment in `environment.yaml`

## Code linting and formatting
After every change, run `snakefmt`, `snakemake --lint`, `black`, and `ruff` for formatting and linting.
